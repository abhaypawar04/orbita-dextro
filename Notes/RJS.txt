B) Primitive vs Reference Types in JavaScript 
JavaScript values are commonly taught as primitive values vs objects (often informally called "reference types"). 

let name = "Rahul";       	 // string
let age = 21;            		 // number
let price = 99.99;       		 // number
let big = 123456789n;    	 // bigint
let isLoggedIn = true;   	 // boolean
let x;                   		 // undefined
let data = null;         		 // null
let id = Symbol("id");   	 // symbol

A primitive value is a single, immutable value. 
let x = "hello"; //"hello" itself cannot be modified. You can make x refer to another string: x = "world"; 
But you didn't modify "hello". You replaced the value associated with x.
Unlike primitive values, objects can generally be modified. 
const user = {
    name: "Rahul",
    age: 21
};
user.age = 22;

console.log(user);  //    {name: "Rahul", age: 22}

But this is true

const b = a;

console.log(a === b); // Output:true

"What's the difference between primitive and reference types?", a strong answer is:
Primitive values are immutable values such as strings, numbers, booleans, bigint, undefined, null, and symbols. When a primitive is assigned to another variable, the value is copied, so changing one variable doesn't affect the other. Objects—including arrays and functions—are mutable values. When an object is assigned to another variable, the reference to the same object is copied, so both variables can access and modify that same object. Technically, JavaScript uses pass-by-value; for objects, the value being copied is the reference to the object.

d) closure 
A closure happens when a function remembers and can access variables from the scope where the function was created, even after that outer scope has finished executing. 

function outer() {
    let message = "Hello";
    function inner() {
        console.log(message);
    }
    return inner;
}
const fn = outer();
fn();
//Hello
Lexical scope
let name = "Rahul";
function greet() {
    console.log(name);
}
greet();
greet() can access name.
Why?
Because name is in an outer scope.
JavaScript determines this based on where the function is written, not where it is called.
This is called lexical scoping.

Nested function : 
function outer() {
    let x = 10;

    function inner() {
        console.log(x);
    }

    inner();
}

outer();  // inner() can access x because inner was created inside outer. 

STRONG DEF : A closure is a function together with the lexical environment in which it was created, allowing it to access variables from its outer scope even after the outer function has finished executing.

e) this 
this keyword refers to the context or object that is currently executing the code 
For a normal function, this is determined by how the function is called, not where it was defined. 
But arrow functions are different: they don't create their own this; they capture it from the surrounding scope. 


this is a special keyword that refers to a value determined by the execution context. 
const user = {
    name: "Rahul",

    greet() {
        console.log(this.name);
    }
};
user.greet();  //Rahul

Here:this refers to:user So: this.name means: user.name

Arrow functions do not have their own this.
They inherit this from their surrounding lexical scope.

SPREAD & REST OPERATOR 

In JavaScript, the spread operator and rest parameter use the exact same syntax (...), but they perform completely opposite actions depending on the context. [1, 2]
The fundamental difference is that the spread operator unpacks elements (spreads them out)
while the rest operator packs multiple elements into a single array (gathers them together).

Spread Operator ⭐
Spread takes elements from an array/object and spreads them out.
//spread with array
const arr1 = [1, 2, 3];
const arr2 = [...arr1, 4, 5];
console.log(arr2);
// [1, 2, 3, 4, 5]

// spread with objects 
const user = {
  name: "John",
  age: 25
};
const newUser = {
  ...user,
  city: "Pune"
};
console.log(newUser);
// { name: "John", age: 25, city: "Pune" }

Rest Operator ⭐
Rest does the opposite.
It collects multiple values into an array.
const [first, ...rest] = [10, 20, 30, 40];
console.log(first);
// 10
console.log(rest);
// [20, 30, 40] ...rest means "Collect everything remaining."
